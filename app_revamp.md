PART 1 — Cognitive Overload Fix (Modification Plan)
1. Collapse the Entry Point

The first experience should not introduce:

journeys
dimensions
companions
alarms
contributions

That’s not onboarding. That’s a stress test.

Replace with:

A single decisive entry:

“Start a Journey”

Nothing else competes with it.

2. Introduce a “Default Path” System

Users should not design their first journey.

They should accept one.

Predefined templates:
Daily Reading → 5 ayahs/day
Memorization Path → 3 ayahs/day + audio
Deep Study → 2 ayahs/day + tafsir

Each template:

auto-selects dimensions
auto-sets pacing
auto-generates deadline

The system quietly does the thinking.
The user just taps Start.

Customization becomes:

a privilege earned after first completion

3. Progressive Disclosure (the app stops yelling everything at once)

Features unlock in layers:

Phase 1 (Day 0–2)
One journey
Ayah view
Mark complete
Phase 2 (After activity detected)
Progress visualization
Page context mode
Phase 3 (After consistency)
Companions
Group journeys
Phase 4
Contributions
Advanced settings

Nothing is removed.
Everything is withheld until relevant.

4. Merge “Dimensions” into a Single Flow

Right now:

Reading, memorization, tafsir feel like parallel systems

That’s mentally expensive.

Replace with:

A stacked progression inside each ayah:

Read
Listen
Understand

Each ayah becomes a mini journey.

Instead of choosing dimensions upfront, the UI subtly guides:

“Next: listen to this ayah”

No decisions. Just progression.

5. Reduce Social Pressure Surface

Social features should feel:

supportive, not invasive

Adjustments:
Hide companion activity by default
Show only:
“X completed 3 ayahs today”
No constant comparisons
No leaderboards (unless carefully designed later)

Group journeys should feel like:

quiet co-travel

Not:

academic competition with anxiety

6. Kill Redundant Surfaces

If a feature doesn’t directly support:

starting
continuing
or completing a journey

…it should not be visible early.

“Contributions” should not sit next to “Journey” like equals.
That’s like putting dessert before someone understands the menu.

PART 2 — UI SYSTEM (Elegant, Premium, Intuitive)

Now for the part where everyone suddenly thinks they’re a designer.

Let’s avoid that tragedy.

1. Core Design Philosophy

The UI should feel like:

A calm, sacred workspace — not a productivity dashboard

Key principles:

Quiet hierarchy
Generous spacing
Minimal color noise
Intentional motion
Content-first, chrome-second
2. Visual Identity
   Color System
   Primary: deep forest green or muted emerald
   Background: warm off-white (not pure white)
   Accent: soft gold for highlights and completion states
   Text: near-black, slightly softened

No neon. No gradients screaming for attention.

This is not a fintech app begging for clicks.

Typography
Arabic text: large, breathable, respected
English: clean sans-serif, medium weight
Clear hierarchy:
Ayah > Translation > Tafsir

Nothing competes with the Quran text.
Everything else supports it.

3. Layout System
   Home Screen (Radically Simplified)

Top:

Greeting or subtle context (“Continue your journey”)

Center:

Primary card: Current Journey
Progress bar
Ayah range
“Continue” button

Below:

Minimal secondary actions:
“Start new journey”
“View companions” (if unlocked)

No clutter. No grids. No chaos.

4. Journey Screen

This is the heart. It must feel… focused.

Structure:
Top: Progress (subtle, not gamified)
Center: Current ayah card
Bottom: Single primary action → “Mark Complete”

Optional actions (secondary, subdued):

Play audio
View tafsir
Switch to page mode

Everything revolves around:

“What is the next ayah?”

5. Ayah Interaction Design

Each ayah should feel like:

a contained, meaningful unit

Interaction flow:
Tap → expand
Swipe → next ayah
Long press → options (bookmark, share)

No cluttered buttons.
Gestures do the heavy lifting.

6. Motion & Feedback

Motion should be:

slow
intentional
reassuring

Examples:

Completing an ayah → soft glow + subtle expansion
Progress update → smooth fill, not jumpy
Transitions → fade/slide, never snap

The app should feel like it breathes.

7. Social UI (Contained, Not Loud)

Companions should live in a separate layer, not the main flow.

Design:
Minimal avatars
Simple stats:
“12 ayahs completed”
Activity feed (quiet, not real-time spam)

No dopamine traps.
Just presence.

8. Audio Experience

Audio UI should feel:

immersive, not technical

Large play button
Waveform optional, but subtle
Loop/repeat controls hidden unless needed

Focus:

listening, not controlling

9. Empty States (where most apps embarrass themselves)

Instead of:

“You have no journeys 😢”

Use:

calm prompts with direction

Example:

“Begin with a short journey. Consistency matters more than speed.”

No guilt. No pressure.

10. Overall Experience

If done right, the app should feel like:

Opening it lowers mental noise
Progress feels natural, not forced
Features reveal themselves when needed
Nothing demands attention unnecessarily
Final Thought

Right now the product is:

powerful but overwhelming

This plan turns it into:

simple on the surface, deep underneath

Which is annoyingly hard to execute, because it requires restraint.

And restraint is where most builders fail, right after adding “just one more feature that could be useful.”
